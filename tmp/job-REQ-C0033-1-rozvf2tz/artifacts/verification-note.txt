    Layout Account-Account Layout (layouts/Account-Account Layout.layout): Field:Name must be Required

Diagnosis (static, from repo contents):
  Account.Name is a required field on the Account object. A layout that places a
  required field must declare it with <behavior>Required</behavior>. The committed
  layout declared <field>Name</field> with <behavior>Edit</behavior>, which the
  Metadata API rejects with "Field:Name must be Required".

Fix applied (single change, cause-level):
  force-app/main/default/layouts/Account-Account Layout.layout-meta.xml
    Account Information section, first layoutItems column 1:
      <behavior>Edit</behavior>  ->  <behavior>Required</behavior>   (for field Name)

  This matches the standard Account layout shape used by Salesforce orgs, where the
  Name field is always the Required item of the Account Information section.

Unchanged and already correct:
  - force-app/main/default/objects/Account/fields/Customer_Priority__c.field-meta.xml
      Picklist, restricted value set with High / Medium / Low, <required>false</required>
      (so existing Account records are unaffected — the field is not mandatory).
  - force-app/main/default/permissionsets/Account_Customer_Priority_Access.permissionset-meta.xml
      readable=true / editable=true on Account.Customer_Priority__c.
  - force-app/main/default/layouts/Account-Account Layout.layout-meta.xml also places
      Customer_Priority__c with <behavior>Edit</behavior> in the
      Additional Information section (viewable + editable from the Account record).
  - FEATURE.md wiring manifest paths all exist on disk and match.
